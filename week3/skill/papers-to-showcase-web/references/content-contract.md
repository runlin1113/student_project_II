# 内容契约

生成器不猜内容，全部从两处读：**两份源笔记**（Markdown）与 **`project.py`**（配置 + 五问答案）。
本文档规定它们的结构。照着写，脚本就能直接跑；写偏了会静默少内容，所以改完一定要看一眼产出。

## 一、`project.py` 字段总表

从 `assets/project.sample.py` 复制后填写。**这是唯一需要按项目改的文件**，脚本一律不改。

### 路径（建议用 `ROOT = 上一级目录` 拼接，避免依赖运行时的当前目录）

| 字段 | 含义 |
|---|---|
| `ROOT` / `p(*parts)` | 项目根目录辅助函数（示例文件里已给） |
| `SUMMARY_MD` | 源笔记 A：要点解读 + 速查表 |
| `TRANSLATION_MD` | 源笔记 B：摘要 / 引言 / 结论译文 |
| `OUT_MD` | 交付物 1：合并版 Markdown 的输出路径 |
| `OUT_HTML` | 交付物 2：展示网页的输出路径 |
| `PAPERS_DIR` | 论文 PDF 目录 |
| `FIGS_DIR` | 取图产物目录（自动创建） |

### 首页与单篇页文案

| 字段 | 含义 |
|---|---|
| `HTML_TITLE` | `<title>` |
| `HERO_H1` / `HERO_LEDE` | 主页大标题 / 一句导语 |
| `BACK_LABEL` | 单篇页返回按钮文字（含箭头，如 `← 返回列表`） |
| `COMMON_HEADING` / `COMMON_KICKER` | 「共同判断」板块的中文标题 / 英文小字 |
| `COMMON_ROWS` | 共同判断的每一行：`(左标签, 结论, 出处, 是否淡化)` |
| `COMMON_CITE` | 面板底部那句观测旁证（最有说服力的一句，别省） |
| `PAPERS_HEADING` / `PAPERS_KICKER` | 卡片区标题 / 英文小字 |
| `FOOTER_LINES` | 页脚列表，每项一行（可含 `<code>` 等行内 HTML），**不要**写前导缩进 |
| `STAR_BADGE` / `PRIORITY_BADGE` | 单篇页两枚小徽标文案；后者用 `%d` 占位序位 |

### 合并版 Markdown 的骨架

| 字段 | 含义 |
|---|---|
| `MD_TITLE` | 文档一级标题（`# ` 之后的部分） |
| `MD_HEADER_LINES` | 头部 `>` 引用块，每项一行 |
| `MD_SECTIONS` | 各章标题（**不带** `## `）：`intro` `table` `papers` `trend` `land` `anchor` `index` |
| `MD_LABELS` | 逐篇字段名：`en_title` `cn_title` `source` `route` `method` `numbers` `star` `priority` |
| `STAR_NOTE` / `PRIORITY_FMT` | ★ 说明文字 / 序位格式（含 `%d`） |
| `SOURCE_SECTIONS` | 源笔记的二级标题前缀：`intro` `table` `detail` `trend` `land` `anchor` `b_index` |

### 分类、配色与论文清单

| 字段 | 含义 |
|---|---|
| `ROUTES` | `[(路线名, CSS 类后缀, 颜色)]`。后缀用短英文（`syn`/`reuse`…），会生成 `.r-<后缀>` 类与 `--<后缀>` 变量 |
| `ACCENT` | 全局强调色（一般取第一条路线的颜色） |
| `PAPERS_META` | `{编号: (路线名, 落位序位, 是否★)}`；序位 0 表示不显示 |
| `SHORT` | `{编号: 卡片短名}`。**长标题必须给短名**，卡片只放得下一两行 |

### 图示

| 字段 | 含义 |
|---|---|
| `FIG_TARGETS` | 每篇一条 dict：`n` 编号 / `name` 文件名用的短名 / `pdf` PDF 文件名（不含 `.pdf`，位于 `PAPERS_DIR`）/ `fig_page` `cap_page` 图与图题所在页 / `label` 图题标签 / `prefix` 图题开头几个词 / 可选 `override=(y0,y1)` 人工兜底 / 可选 `note` 降级说明 / 可选 `substitute=True` 标记替代图 |

### 五问内容

| 字段 | 含义 |
|---|---|
| `Q_TITLES` | 五问标题（见第三节，一字不改） |
| `QA` | `{编号: [答案1..答案5]}`，整段 Markdown |

## 二、两份源笔记的结构约定

### 源笔记 A（要点解读 + 速查表）

二级标题用固定前缀（映射见 `SOURCE_SECTIONS`）：

```markdown
## 〇、这批论文的共同判断        ← 原样抄进合并版
## 一、速查表                  ← 必需，卡片与逐篇字段都取自它
## 二、逐篇要点                 ← 每篇一个 `### N. 标题`
## 三、趋势判断                 ← 原样抄进合并版
## 四、落位建议                 ← 原样抄进合并版
## 附：其他                    ← 原样抄进合并版
```

**速查表是本流程的数据源，格式必须严格**（第一行表头，之后每行第一格是论文编号）：

```markdown
| 编号 | 短名 | 中文名 | 核心方法 | 关键数字 | arXiv |
|---|---|---|---|---|---|
| 1 | EnvCraft | 环境合成… | 一句话方法（卡片"方法"栏用它） | 一两个可引用的数字 | `arXiv:2609.05576` |
```

- 第 4 列（索引 3）→ 卡片的「方法」一句话与逐篇 Markdown 的「核心方法」
- 第 5 列（索引 4）→ 逐篇 Markdown 的「关键数字」
- 少了这两列，卡片会空着，不报错

### 源笔记 B（三段译文）

```markdown
## 1. EnvCraft —— 环境合成
**中文标题**：……（可选，会覆盖卡片副标题）
`arXiv:2609.05576`（2026-09-04）
### 摘要
### 引言
### 结论
附：PDF 与抽取文件索引        ← 最后一个二级标题，原样抄进合并版末尾
```

- `## N.` 的编号必须与速查表一致
- `**中文标题**：` 与 `` `arXiv:…`（日期）`` 都是按行正则抓取的，**写成一行、不要换行**
- 三个 `###` 小标题名称固定，缺哪段就在页面上显示「（缺）」

## 三、五问标题与写作约束

标题**固定，一字不改**（它们是交付外观的一部分）：

```
1. 这个工作解决什么问题
2. 怎么解决的
3. 为什么可以解决？
4. 如何证明有效性（用什么数据集）
5. 我们的机会点
```

| 问 | 要写成什么 | 容易写错成 |
|---|---|---|
| 1 | **它诊断的问题**，含上一代方法的死结（"现有 X 只做到 A，撑不起 B"） | 它做了什么 |
| 2 | 机制链条：A 做 X → B 做 Y，可带规模数字 | 罗列优点 |
| 3 | **机制层面的理由**（这条路为什么成立） | "因为实验效果好" |
| 4 | **基准名 + 数字**（便于用户写方案时直接引用） | "作者做了大量实验" |
| 5 | 对用户课题的机会点，**开头用加粗亮出那句判断**，后接具体做法 | 泛泛的"值得借鉴" |

其他约定：

- 内容只能取自该篇的摘要 / 引言 / 结论与原文数字，**不引入外部信息**。
- 允许行内 Markdown：`**加粗**`、`` `行内代码` ``（渲染成 `<strong>` / `<code>`）；不要用标题与列表以外的块级语法。
- 第 5 问会以**通栏琥珀卡**呈现，是整页视觉焦点，不要写空话。

## 四、展示口径（写进交付说明与页脚）

- **译文口径**：只译正文 prose；图表内文字与数学符号不逐字译；关键术语保留英文或括号注原文。
- **核验口径**：arXiv 编号与日期以官方页面为准，注明核验日期；不凭记忆写。
- **版权**：图示版权归原作者，页面仅供内部研读，页脚要写明。
- **降级项**：任何替换图、缺失图、图题异常，都要在页面上（`.fignote`）与回复里说明，不要静默处理。
