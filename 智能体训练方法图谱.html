三、27 篇论文逐篇映射（解决的问题 → 所处阶段 → 对应方法维度）

#论文方法维度 主战阶段解决的问题关键解法
1EnvCraft环境生成S1 现有环境只到「应用级工具端点」，撑不起系统级（claw-like）智能体必需的跨环境执行、有状态工作区与异步任务循环。 环境合成引擎 + 拓扑感知数据生成引擎，自动造 139 个交互式环境与连贯任务轨迹。
2Terminal-Universe环境复用S2S4 真实可执行环境稀缺；轨迹只是冻结示范，质量受限于生成策略，且无法核查它对代码库的修改是否正确。 复用海量终端轨迹建训练集，并将轨迹与环境对齐做正确性校验。
3Environment Evolution环境生成S1 从零合成的环境随前沿模型变强而过简单，RL 拿不到区分优劣的梯度，环境只能丢弃、建造成本白费。 难度随学习者演化的环境进化机制，保持训练分布多样性。
4CloudEmu环境生成S1S5 DevOps 程序测试必须打真实云，贵/危险；人工云模拟器覆盖不足（AWS 240+ 服务，最先进仅覆盖 95 个）。 神经符号代码合成自动造云模拟器 + 真云 oracle 自测自愈，覆盖/精度超 LocalStack。
5EnvHarness环境复用S1S3 手工静态环境视而不见自身弱点，随智能体改进迅速落后；近期生成法仍产出静态环境。 可复用环境 harness + 对环境的自省/自改进，提供稳定可复现训练场。
6SPADE环境生成S1 训练环境池（手工/静态合成/冻结验证器）目标分布固定，智能体耗尽题库即停步。 自扩展、多样、自适应的目标池，持续生成任务。
7FACET环境生成S1 任务「指令+初始环境+参考解+验证器」四件套若由不一致假设生成，会不可解且验证器虚构打分。 高质量终端任务四件套联合合成 + 一致性验证，杜绝不可解任务。
8Agentic Game Dev轨迹生成S2S3 世界模型奖励靠 CLIP 分等模糊代理，有噪、有偏、可钻空子。 借鉴代码智能体：用编译器/测试/运行时等可执行反馈替代模糊奖励。
9RLSVR / SpyRL轨迹生成S2S3 RLVR 只在数学/代码有效（可判定）；开放式任务无 checker，退回偏好/裁判模型带来偏差与天花板。瓶颈是可验证性。 可验证奖励（RLVR）+ 过程验证，扩展「可判定域」让自改进不被判卷人卡住。
10ESAT环境生成S1S2 训练 API 智能体需海量多步轨迹，但环境创建与数据合成紧耦合，是扩展性主要瓶颈。 解耦环境创建与数据合成，自动造 API 调用多步轨迹（指令/读写/结果/响应）。
11AgentBench基准测评S4 缺在交互式环境里系统量化推理与决策能力的基准；多数评测静态/单环境，无法横向比较。 多维、可复现、覆盖多种真实环境的统一评测框架。
12SWE-bench基准测评S4 LM 基准被刷爆、脱离真实；真实软件工程可持续但缺可执行评测环境。 真实 PR + 可执行测试自动验证（既难到能难住模型，又易自动验证）。
13WebArena基准测评S4 Web 智能体环境过度简化、功能残缺、多为静态缓存，与真实 Web 脱节。 自托管真实 Web + 程序化功能验证，保证真实可复现。
14τ-bench基准测评S4 现有基准不测智能体与真实用户的动态交互、也不测其遵循领域规则的能力。 用户模拟 + 领域规则 + 随机性，在「有用户、有规则」条件下评测一致性。
15OSWorld基准测评S4 现有基准无交互环境或只限特定应用，无法覆盖真实计算机使用的多样与复杂。 跨 OS、跨应用、可执行的统一真实计算机环境。
16AWM环境生成S1 规模化瓶颈是缺多样可靠环境；真实环境贵、人工环境缺多样、LLM 模拟有幻觉且贵。 抽象世界模型 + 可复用模块合成多样可靠环境。
17Agent-World环境生成S1 开放世界工具环境天然组合式、有状态；静态/单工具不够，且「可扩展真实感 + 自进化训练」两瓶颈未解。 组合式有状态工具环境 + 持续自进化训练机制。
18EnvScaler环境生成S1 真实系统访问受限、LLM 模拟有幻觉、人工沙盒难扩展，且程序化方法缺自动质量评估。 可扩展沙盒合成 + 自动质量评估。
19LogicEnvGen环境生成S1 仿真环境重「视觉真实」而轻「逻辑多样性」（同目标下状态/条件多变），导致评测不全。 强调逻辑多样性，显式构造多变的状态与条件。
20InfiniteWeb环境生成S1 GUI 智能体训练受限于环境稀缺；Web 基准手工、规模小、难泛化；LLM 写不出多页互联的正确网站。 自动生成多页互联、功能正确、风格多样的完整网站环境。
21Self-Instruct轨迹生成S2 指令微调依赖昂贵、有限的人工标注指令数据，量与多样性都不足。 模型自生成指令→回复，bootstrap 低成本指令数据。
22ReAct轨迹生成S2 推理（CoT）与行动此前分开：纯行动缺推理、纯推理缺外部交互。 在同一条轨迹里交错推理与行动（思考→动作→观察）。
23FireAct轨迹生成S2 多数语言智能体靠少样本提示现成 LLM，性能/鲁棒性/效率受限；「微调智能体」被忽视，且缺轨迹数据。 用合成轨迹微调智能体 + 推理轨迹，提升鲁棒性。
24AgentOhana轨迹生成S2 多源智能体数据高度异构（多轮轨迹格式不一），难统一用于训练；来源均衡与跨设备随机性未处理好。 标准化多源轨迹格式，统一联合训练。
25AutoAct轨迹生成S2 智能体学习依赖昂贵不可复现标注，或依赖闭源模型（GPT-4）合成规划轨迹；单模型难担多职能。 自动化分工（规划/工具/反思）自造轨迹，不靠闭源模型、不靠大量标注。
26Simia环境生成S1S2 训练依赖为特定任务手工搭模拟台，成本高、易碎、难扩展；开放真实任务中表现脆弱。 LLM 自当环境模拟器（Simia-SFT 轨迹合成 + Simia-RL 在模拟反馈里做 RL）。
27Terminal-Bench基准测评S4 缺在真实可复现 CLI 环境里对长时域自主行动（软件工程/科研/安全/ML）的严格评测。 Docker 沙箱 CLI + 89 个三人核验任务 + 程序化验证（pass@1）。

四、「上云服务智能体」训练 · 问题→方法集合

「上云服务智能体」指操作云基础设施的 LLM 智能体：部署服务、编写/执行 IaC（Terraform 等）、调用云 CLI/API、做资源管理与故障排查（对应 CloudEmu / Azure Copilot / AWS DevOps Agent 的目标）。下表给出其训练全流程中最可能出现的 6 类问题，及可直用的四方法维度与论文。

一句话总结：把「上云服务智能体」的训练看成一条流水线——环境生成 + 环境复用 解决「没地方练」（C1/C5/C6），轨迹生成 解决「没数据练、练歪了」（C2/C3），基准测评 解决「练得行不行、上线会不会翻车」（C4/C5）。四方法维度不是并列工序，而是对同一条流水线的不同补强视角。
